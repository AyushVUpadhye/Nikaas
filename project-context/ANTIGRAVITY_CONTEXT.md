## 3. Strict Development Rules & Constraints

1. **Frozen Data Contract (`docs/CONTRACT.md`):**
   Never modify API response shapes or JSON building schemas without prior build lead (Chirag) approval. All downstream consumers (`web/`, `sim.py`, `optimise.py`) depend on this shared contract.
2. **Deterministic & Testable:**
   All simulation and optimization algorithms must remain deterministic. Use `seed=7`. Same input must produce bit-for-bit identical frames and times.
3. **No Made-Up Numbers:**
   Every number cited in the README, pitch slides, or UI comparisons must be generated by a script that writes to `runs/results.csv` or `runs/wow.csv`.
4. **Preserve Fallbacks:**
   - If Bedrock vision is unready or noisy: Fallback to pre-digitised `data/lab_block.json` or `data/iit_kgp_museum.json`.
   - If 3D Three.js view is incomplete: The 2D Canvas/SVG player is the live demo.
   - If AWS deployment drops offline: Use `uvicorn` locally on `localhost:8000` or `?demo=1` frame replay.
5. **Clean Git Practices:**
   - Commit at least hourly.
   - Local branch `main` tracks `origin` (`AyushVUpadhye/Nikaas`) and pulls from `upstream` (`thegoodengineers/Nikaas`).
   - Always verify test suite before pushing.
